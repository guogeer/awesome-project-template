# yellow-dog 规范提炼

> FaceFlip AI：C 端 App（Flutter）+ App 后台（FastAPI）+ 运营后台（React/antd）。真源：项目仓库 `AGENTS.md`（772 行）+ `doc/`。

## 规范组织方式（本项目最大特色）

- **AGENTS.md 是代理工作约束的总入口**：仓库边界、项目定位与现状、各端技术栈口径、环境/部署、完成定义、排障入口。
- `doc/` 按主题分层：接口契约（`API-*`）、设计文档（`DESIGN-*`）、按日归档的排障/交接记录（`doc/2026MMDD/`、`doc/project-handover/`）。
- **结论落文档，不留暗知识**：方案定稿、域名/桶/CDN 配套关系、基线失败清单都写进 AGENTS.md 或 doc/，AI 每轮自动读到。
- skills 常驻化：`auto-commit-push`（alwaysApply）+ `dev-service-refresh`，把"提交推送""刷新 dev 服务"从人工流程变成收尾自动动作。

## 关键口径（可跨项目复用）

- **配置真源是服务器 `.env`**：仓库里只有模板；compose 默认值只是兜底，`.env` 显式覆盖才生效；改配置必须 `--force-recreate`（restart 不刷新环境变量）。
- **排查配置漂移**：对比运行环境 `.env` 与 `env.<环境>.example` 的非敏感键差异（跳过含 KEY/SECRET/PASSWORD/TOKEN/DSN 的键）。
- **对外文案与根因分离**：接口返回统一通用文案（如"生成服务暂时不可用"），根因以 `xxx failed:` 原文落日志；排查别只看接口返回。
- **写入桶与对外 CDN 必须配套**：正式桶↔正式 CDN、测试桶+前缀↔测试 CDN，配错的表现是资源 403/404 而"URL 看起来正常"。
- **同一张表别混同名前缀的状态列**：`tasks.status` 是审计列（1=正常 2=禁用），业务状态在 `tasks.task_status`；写错不报错、静默恒假（曾导致只扣不退、列表筛选恒空）。
- **展示字段不得当逻辑输入**：模板 `title` 是展示短名，不能当生成提示词兜底——能下单但结果不对，且掩盖同步漏字段。
- **基础定价后台可配置**：App 端单行表存价，运营改完立即生效、不用重启；代码常量只做缺行兜底；展示与扣费必须用同一份配置快照。
- **单测覆盖不到 MySQL 语义**：会话锁/行锁/死锁/连接池在 SQLite 单测里全绿≠验证过，必须真 MySQL 起服务验证（如锁跨 asyncio loop 的坑）。
- **同步表即真源、无缓存**：上游同步数据落同步表，应急修数据直接 UPDATE 同步表即时生效；但下次同步会覆盖，根治要在上游补字段。

## 已验证的坑（教训清单）

- 幂等退款靠业务键（`biz_id=<id>:refund`），失败补偿先落失败状态再退款。
- 判定失败用业务列 `task_status`，不是审计列 `status`。
- Wan3 类订单缺必填提示词在下单组装期就 raise，对外表现为通用文案，日志才是原文。
- restart 不更新容器环境变量；后台 `docker compose pull` 会被 session 清掉，必须前台执行。
