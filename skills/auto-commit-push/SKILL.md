# 自动提交并推送

## Overview

把本次任务产生的改动收敛为一次语义清晰的 git 提交，并推送到 `origin`。提交前做变更审查，提交信息遵循 `docs/git/commit-convention.md`（本仓库模板版）。

## 何时使用

- 用户明确要求提交 / 推送（含任务开始时说的"改完自动提交推送"）。
- **授权场景（无需用户开口）**：项目 `AGENTS.md` 声明本技能 `alwaysApply: true` 或已长期授权时，AI 判定任务完成即执行。

### 收尾自检（每轮都要做，不要等用户开口）

改动跑完校验、准备回复用户之前，先过一遍判定清单：命中就执行提交 + 推送再回报；不命中要在回复里写明卡在哪一条。

**触发前提**：本轮产生了属于本次任务的**任何文件改动**（代码、文档、配置、skill、脚本、静态资源都算）。纯文档/配置改动跳过测试门槛。

四条同时满足即提交推送：

1. 任务目标已达成：功能/修复写完，没有断点，本轮为该改动写的文档、迁移、配置算同一批；
2. 改动归属清晰：是本轮自己改的、属于本次议题，不是别的会话/任务的残留；
3. 涉及代码改动时，**增量测试已跑完且全绿**；改动前就红的**基线失败不算阻塞**（判定：失败用例与本轮改动不碰同一批文件/不涉及本轮语义即按基线处理，拿不准用 stash 验证一次）；
4. 用户没说"先别提交 / 等我确认 / 还要再改"。

**不要提交**：任务未达成、半成品或探索性试写、用例红了未修（非基线）、用户明确暂缓、detached HEAD。

## 硬约束

- 只在目标仓库内执行 git 命令；不改 git config、不 `--no-verify`、不 force push。
- **一任务一提交**：多个独立功能点拆成多次提交；同一功能点的实现 + 用例 + 迁移 + 文档属同一次提交。
- 用户只说"提交"（不含推送）时用 `--no-push`。

## 工作流

### 1. 摸清状态

```bash
git status -sb
git branch --show-current
git diff --stat
```

detached HEAD 或不在预期分支时先向用户确认。多会话并行时先分清改动归属。

### 2. 审查改动并锁定本次任务的路径

- 逐个判定归属，产出路径清单传给脚本；归属存疑的先问用户。
- **必须拦下**：密钥与凭据（`.env` 实体、`*.pem`、`*.key`、`*.p12`、`*.keystore`）、构建产物与依赖目录（`build/`、`node_modules/`、`dist/`、`__pycache__/`）、本地日志与临时文件。发现该忽略却未忽略的，先补 `.gitignore` 再提交。

### 3. 跑测试（涉及代码改动时的硬门槛）

只跑与本次改动相关的用例（改动用例 + 被改动公共层直接影响的既有用例），不要求全量；无测试覆盖时以静态校验兜底并点明。测试红了先修到绿再提交。

### 4. 生成提交信息

按 `docs/git/commit-convention.md`：`<type>(<scope>): <中文 subject>`，必要时 body 写"为什么"。

### 5. 提交并推送

```bash
bash skills/auto-commit-push/scripts/commit_push.sh \
  -m "feat(api): 新增定价配置接口" \
  <path...>
```

脚本做：定位仓库根 → 校验分支与路径 → 敏感文件拦截 → 按路径 `git add -A --` → `git commit` → `git push`（无 upstream 自动 `-u`）。

| 参数 | 作用 |
| --- | --- |
| `-m "<msg>"` | 提交信息（必填） |
| `<path>...` | **必填**（或显式 `--all`）：只提交这些路径 |
| `--all` | 提交工作区全部改动（仅在确认无其他会话残留时用） |
| `--no-push` / `--dry-run` / `--allow-sensitive` | 只提交不推送 / 只打印动作 / 放行敏感文件 |

### 6. 处理推送异常

- `non-fast-forward`：先 `git pull --rebase origin <branch>`，解决冲突后重推，不强推。
- 认证失败：提示用户检查 SSH key / 网络（多账号项目确认 `~/.ssh/config` 分流），不改 remote。
- 22 端口不通（`Connection timed out`）：**提交已落盘，不要回滚**，用 443 端口补推：

```bash
GIT_SSH_COMMAND="ssh -p 443 -o StrictHostKeyChecking=accept-new" \
  git push ssh://git@ssh.github.com/<owner>/<repo>.git <branch>
```

### 7. 回报

给出：分支、提交 hash 与 subject、改动文件数、推送结果（远端分支）。

## 常见错误（别再犯）

- 以为"用户没说提交就不提交"——已授权仓库默认就是要提交，每轮收尾过一遍清单，不要积压。
- 基线失败挡住整批改动——基线失败不算阻塞，提交时注明即可。
- 忘记技能只在 `<项目>/.codebuddy/skills/` 下可见——副本放别处不会被加载，发现缺失先补副本。
- 裸 `git commit` 把别的会话的改动一起带走——必须走脚本按路径提交。
