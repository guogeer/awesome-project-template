# 提交信息规范

> 提炼自 yellow-dog 仓库已验证口径，复制到项目后按目录调整 scope 表。

## 格式

```
<type>(<scope>): <subject>

[可选 body: 为什么这么改 / 影响面 / 迁移与回滚注意]
```

- subject 用**简体中文**，动词开头，省略句号，控制在 50 字内。
- 一句话能说清就不写 body；涉及迁移、破坏性变更、需要人工跟进的操作（远端清理、证书更换等）才写 body。
- 不加 AI 署名、不加 `Co-Authored-By` 之类的 trailer。

## type 取值

| type | 用于 |
| --- | --- |
| `feat` | 新功能 / 新页面 / 新接口 / 新迁移 |
| `fix` | 缺陷修复 |
| `refactor` | 重构，行为不变 |
| `perf` | 性能优化 |
| `style` | 格式、样式调整，无逻辑变化 |
| `test` | 测试增删与调整 |
| `docs` | 文档（`docs/`、`README`、`AGENTS.md`） |
| `chore` | 依赖、脚本、配置、部署编排 |

## scope 取值

按改动所在目录选，缺省时可不写 scope。示例（按项目实际目录替换）：

| scope | 目录 |
| --- | --- |
| `api` | 后端服务 |
| `web` | 前端页面 |
| `app` | 移动端 / 客户端 |
| `docker` | 部署编排 |
| `docs` | 文档 |
| `skill` | skills 目录 |

跨多个目录且不便于拆分时，取主体改动所在的 scope；前后端必须一起上时，可省 scope。

## 示例

```
feat(api): 新增定价配置接口与后台页面
fix(api): 修正任务失败判定误用审计列导致只扣不退
refactor(api): 抽离钱包入账到 wallet_service.grant 并加幂等约束
docs: 补充错误处理规范中的幂等口径
chore(docker): deploy.sh 支持 --tag 指定镜像版本
```

## 迁移类改动

涉及数据库迁移时，在 body 写明迁移版本号与是否需要手工回滚：

```
feat(api): 新增定价配置表并播种默认值

迁移 0033_pricing_configs.py，回滚需先 downgrade 再发版。
```

## 一任务一提交

- 多个相互独立的功能点（不同需求/缺陷、不同端）**拆成多次提交**，每次单独过一遍审查与测试流程。
- 同一功能点的实现 + 用例 + 迁移 + 文档属同一次提交；禁止把一个功能点拆成多个半成品 commit。
- 提交前确认工作区没有混入其他会话/任务的残留改动——只 `git add` 本次任务明确改过的路径。
