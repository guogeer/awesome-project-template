# 数据脱敏规范（模板）

## 通用原则

- **分类先行**：动手前先识别数据是否属于敏感类——用户个人身份信息（姓名、手机号、邮箱、身份证、地址）、账号凭据（密码、token、API key、支付凭据）、资金与订单明细、第三方归因标识（设备 ID / IDFA / GAID / AppsFlyer ID）等。判不准的按敏感处理。
- **最小化**：日志、埋点、错误上报、测试夹具、演示数据只采集和保留完成任务所必需的字段；能不存的明文一律不存。
- **入口到出口全链路约束**：脱敏不是单点——落库、写日志、对外响应、导出文件、复制到测试环境，每一跳都要检查。

## 落库与展示

- 密码禁止明文落库，只存加盐哈希（bcrypt / argon2id）；`password` 类字段**只进不出**，任何响应、序列化、日志都不得出现。
- 展示层脱敏（手机号 `138****1234`、邮箱 `a***@example.com`、卡号保留末 4 位）；API 响应字段按需返回，不整对象透传。
- 唯一性判定用哈希或归一化值，不要为了去重把明文再存一份。

## 日志与排障

- 密钥、token、支付凭据、密码**不落日志**（error-handling.md 已有此约束，这里是硬性红线）。
- 结构化日志需要请求体/响应体时，敏感字段做掩码或替换（如 `"email": "a***@e.com"`）；脱敏工具函数集中维护，不要在各处手写正则。
- 导出日志、堆栈、HTTP 抓包用于排查前，先确认不含敏感原文；贴给外部（工单、第三方、文档）必须先脱敏。

## 测试与数据迁移

- 测试库、本地 dev、演示环境的用户数据用**合成数据**或脱敏副本，禁止把生产明文数据直接灌入。
- 从生产导数据到测试环境必须走脱敏管道（可识别字段：姓名 / 邮箱 / 手机号 / 地址 / 凭据），并保留脱敏脚本可审计。
- 快照、备份、dump 文件不入仓、不落公开目录（对象存储 / 共享盘按敏感级别控制访问）。

## 配置与凭据

- 客户端不硬编码密钥、支付凭据或 Secret；模型 / 第三方调用一律经后端代理。
- 凭据只进环境变量或密钥管理；`.env` 真值文件不入仓（仓库里只有 example / 模板）。
- 文档、README、AGENTS.md 示例一律用占位符（`<API_KEY>`、`sk-***`），不写真实域名配套的真实密钥。

## 提交与协作红线

- 不提交真实密钥、生产地址配套的凭据、用户真实数据样本；发现误提交立即作废轮换该凭据（光删文件不够，历史里还在）。
- 需求文档 / bug 报告里出现的用户数据一律打码后再流转。
