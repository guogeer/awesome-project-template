# 技术栈细则：React 管理后台（antd + Vite）

> 复制到管理后台项目后按实情裁剪；通用风格见 `code-style.md`。

## 依赖版本一致性

- `package.json` 升级大版本后**必须重装 `node_modules`** 再判断代码是否真的红——本机环境的本机 npm 有批量删除保护，`rm -rf node_modules` 可能被拦，先把旧目录 `mv` 到 /tmp 再 `npm install`。
- 大版本升级（如 antd 5→6）后旧 API 报错很多是"依赖没重装的假错"：先重装、再 typecheck，别急着按报错改代码。
- 构建含 `tsc --noEmit` 时，typecheck 红 = build 红；typecheck 是提交前静态校验的一部分。

## 组件用法

- antd 组件按当前大版本的 API 写，不凭旧版本记忆；拿不准查 node_modules 里实际安装版本的类型定义。
- 表格 / 表单 / 抽屉等复杂组件的测试断言跟随组件实际 DOM 结构，升级后优先怀疑选择器过期。

## 页面与权限

- 每个页面对应权限点（如 `pricing:view` / `pricing:edit`），路由与按钮双控；后端为真源，前端只做展示控制。
- 列表页统一模式：筛选区 + 表格 + 分页，状态入 URL query，刷新不丢。

## 数据与契约

- 请求层单例：统一 base URL、鉴权头、错误信封拦截（401 跳登录、业务 code 统一提示）。
- 后端下发的配置（定价、渠道等）**每次现查不缓存**或明确缓存失效时机，避免改配置后台看不到变化。

## 测试

- 关键交互（表单提交、权限入口、状态流转）配 vitest 用例；断言用户可见行为而非内部状态。
- 升级依赖后偶发失败的用例先单独跑一次判断是否 flaky，再决定修用例还是修组件。
