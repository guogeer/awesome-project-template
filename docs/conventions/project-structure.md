# 目录结构规范（模板）

> 复制到具体项目后，按技术栈填充各层职责。

## 通用原则

- **按职责分层，不按文件类型堆砌**：同一业务域的模型/服务/接口放在可预测的位置，新人按名字能猜到路径。
- 配置与代码分离：环境参数进 `.env` / 配置文件，**禁止硬编码**密钥、域名、上游地址。
- 部署与运维产物集中在一个目录（如 `docker/`、`deploy/`），并配 README 说明。

## 推荐布局（按项目裁剪）

```
├── AGENTS.md            # AI 代理工作约束（仓库根）
├── README.md
├── CHANGELOG.md
├── doc/ 或 docs/        # 设计文档、接口契约、运维手册
├── src/ 或各端目录       # 源码（多端项目按端分顶层目录，如 app/ admin/）
│   ├── models/          # 数据模型 / 实体
│   ├── services/        # 业务逻辑（事务边界、幂等控制在这里）
│   ├── api/ 或 routes/  # 接口层（只做参数校验与编排，不写业务）
│   └── utils/           # 无状态工具函数
├── migrations/          # 数据库迁移（只增不改；回滚写明前置条件）
├── tests/               # 测试（目录结构与 src 对应）
├── scripts/ 或 tool/    # 开发/运维脚本
└── .github/             # CI、PR/Issue 模板
```

## 关键约定

- **迁移文件只增不改**：已合入主干的迁移禁止修改，需要调整就新增迁移；提交信息里写明迁移版本与回滚注意。
- **文档落库**：方案定稿、接口契约、排障结论写成文档进仓库，不留散落在聊天记录/日志里的"暗知识"；按 `YYYYMMDD` 或主题命名归档。
- **临时产物不入库**：日志、构建产物、本地配置（`.env` 实体）一律 `.gitignore`；`.env.example` 入库作模板。
- git 子模块：独立演进的部分拆成子模块，登记 `branch`；克隆后先 `git submodule update --init --recursive`。
